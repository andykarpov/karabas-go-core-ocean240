# План ядра «Океан-240» для Karabas Go / Mini / Mini G

Цель: ядро ПЭВМ «Океан-240» / «Океан-240.2» (Д. А. Тилинин, Институт океанологии АН СССР, 1985–1986): КР580ВМ80А 2,4 МГц, ОЗУ 128 КБ (основное + «электронный диск»), ПЗУ 16 КБ, графика 512 × 256 монохром / 256 × 256 × 4 цвета из 8 палитр, аппаратные сдвиги экрана (240.2), ВВ55 × 4, ВИ53, ВН59, ВВ51, магнитофон, Bell; дисковод ВГ93 — позже. Платы Karabas (XC6SLX25, ISE 14.7). Файлы идут через прошивку (OSD, `FL`, `F`, burst): загрузчика и soft-CPU в ядре нет. Железо: `docs/HARDWARE.md`. Вопросы: `docs/BACKLOG.md`.

## Решения (пользователь 2026-11-25)

1. **Своё ядро по схеме** реплики romychs (+ МПСС), без чужого RTL как основы. Сверка с MAME / Emu80 / JS, заимствования только справочные.
2. **Модель выбирается в OSD** (240 / 240.2 и т. п.). Модель — набор осей, а не только имя: сдвигатели экрана (нет / есть), интерфейс клавиатуры (ASCII-контроллер со стробом / матрица), набор ПЗУ, порты 20–25 (ВВ55 DD80 / ВГ93), ОЗУ 128 / 512 КБ. Пресеты пункта «Модель» определяем в Ф0 по разбору ПЗУ; черновик:
   - **240** — Монитор 240/7 + CP/M без дисковода, ASCII-клавиатура (MAME `okean240`);
   - **240.2** — то же + сдвигатели C0 / C2 (Монитор 240/7 их уже пишет — проверить, что он делает на машине без них);
   - **240 Turbo / FDD** — HARDWARE MONITOR+ + CP/M с дисководом, матричная клавиатура (MAME `okean240a`) — после ВГ93.
3. **Дисковод делаем, но не в первой версии**: отдельная фаза после релиза v1. Порты 20–25 в дешифраторе свободны с самого начала.
4. **Репозиторий локальный** (`karabas-go-core-ocean240`), на GitHub — к первому релизу, по слову пользователя. Ядро GPL v3.
5. **Порядок плат:** Mini G сначала, Go и Mini в фазе релиза. Id ядра `ocean240`, файл `ocean240.kg`, каталог SD `/ocean240`.
6. **Все ПЗУ — в репо и в `.kg`** (пользователь 2026-11-25): Мониторы 240/7 и HARDWARE MONITOR+, CP/M с дисководом и без, тесты, РТ4 палитры и контроллера дисковода (дампы romychs, BSD-3). Пресет модели выбирает набор; `FL` — для своих ПЗУ пользователя.
7. **Модели — все со сдвигами экрана** (пользователь 2026-11-25, «делай сразу со сдвигом»): пресеты «240.2» (Монитор 240/7 + CP/M REL.5, клавиатура ASCII), «Turbo» (HARDWARE MONITOR+ + CP/M REL.7/2D, позиционная клавиатура), «Тест» (тест-программа МПСС); «240» без сдвигателей и пункта «сдвиги выкл.» нет.

## Архитектура (черновик, уточняется в Ф0)

```
                ┌── CPU vm80a (ce 2,4 МГц, Ф1 / Ф2 как у specialist), INTA → ВН59 (CALL, 3 байта)
 ocean_system   ├── ОЗУ 128 КБ (/512) + ПЗУ 16 КБ в SRAM; коммутация по C1 (табл. 1 МПСС), старт ПЗУ0 везде
                ├── видео-ЗУ: копия 2 × 16 КБ в BRAM (страницы E1 B7), запись ЦП дублируется — ЦП не ждёт
                ├── видео: счётчики строк / слов, VS (C0) и HS (C2) для 240.2, ПЗУ палитры РТ4 (256 × 4) + фон
                ├── ВВ55: DD78 (40, клавиатура, гашения, лента in), DD17 (C0), DD67 (E0), DD79 (00), DD80 (20)
                ├── ВИ53 (60, клок 1,536 МГц), ВН59 (80), ВВ51 (A0) → USB-UART MCU (порт 0)
                └── звук: Bell (E2 C3), ЦАП ленты (E2 C0–C2) → PCM; лента in → 41h B2 / B3
 kg_mcu ────── ROM loader, FL (ПЗУ, образ «электронного диска»), HID, переключатели, UART
 верх платы ── PLL, удвоитель строк → HDMI, kg_osd_overlay, звук, базовый набор платы
```

Клок: 4 × кварц. Если кварц 12,288 МГц (схема) — 49,152 МГц, пиксели 12,288, ЦП 2,4576, ВИ53 1,536, HDMI 24,576 × 5. Если 12,0 (МПСС) — 48 МГц, как Вектор. Выбор — Ф0 (расхождение 1 в HARDWARE.md). HDMI: родной кадр с удвоением строк (как Вектор-06Ц, 576p-подобный), если кадр Океана близок к 625 / 50; иначе — буфер кадра. Решение — по счётчикам DD24–DD27 в Ф0.

## Фазы

Одна ветка на фазу, один PR в конце (локальный master до публикации).

### Ф0. Схема, ПЗУ и машина в симуляции
- `tools/fetch_upstream.sh`; разбор схемы romychs (CPU, RAM_CTR, Video, Interfaces) → `docs/HARDWARE.md` без пометок «черновик»: кварц и клоки, длина строки и кадра (DD24–DD27), биты C1 (B1–B3, B6, B7) и подтяжки DD17, разводка адресов DD66 (ПЗУ палитры) и полярность выходов, клавиатурный разъём X2.
- Разбор ПЗУ (IN / OUT, точки входа): какой Монитор что ждёт от клавиатуры, сдвигателей, портов 20–25; что делает CP/M с дисководом без ВГ93 → пресеты пункта «Модель».
- Синхронный `ocean_system`: vm80a, SRAM-обёртка (от `v06c_sram`), коммутация памяти, ВВ55 × 3 (DD78, DD17, DD67; DD79 / DD80 — заглушки-регистры), ВИ53, ВН59 (KF8259 в режиме 8080), минимальный ВВ51 (передатчик + статус), копия видео-ЗУ, видео 512 × 256 / 256 × 256 со сдвигами.
- Проверка `k580vv55`: после сброса порты в «Z» (читается 1 → C1 = FFh → ПЗУ0 везде), после слова режима — 0. Иначе ЦП не стартует.
- Verilator: (1) ПЗУ тестов — «TEST 1 PASSED» … «TEST 8 PASSED» на ВВ51 (тест 8 = таймер + ВН59), тест 2 — кадры в PNG (шахматы, сдвиги, монохром, фоны); (2) Монитор 240/7 — приглашение на экране (кадр PNG); (3) CP/M — `A>`.
- `make ocean-xst`: размер машины, без защёлок.

**Итог Ф0 (2026-11-25):**
- **Схемная модель реплики** (`src/sim/schem`): нетлист KiCad → структурный Verilog (`gen_schem.py`), модели ТТЛ по выводам (`ttl.v`: '00…'298, РУ7, 27256, РТ4) и БИС 580 (`lsi.v`), vm80a; Icarus, ~2 с на 1 мс машины. Дала: кварц 12,288 МГц, ЦП 2,4576 МГц, растр 768 × 320 (62,5 мкс, 49,99 Гц), биты C1 (B1–B3 = страница 64 К из 512 КБ, B6 / B7 — банк ПЗУ), адрес видео-ЗУ, порядок бит на экране, окно BLNK, «TEST 1 PASSED». Две гонки модели (перенос '193 → загрузка сдвиговых, удержание выхода РУ7 после ~CAS) исправлены задержками из справочника.
- **Машина в RTL** (`src/rtl/ocean`): `ocean_system` (клок 49,152 МГц, vm80a без ожиданий, SRAM: ОЗУ 512 КБ + ПЗУ0 / ПЗУ1 по 32 КБ), `ocean_video` (копия видео-ЗУ 2 × 16 КБ в BRAM, счётчики, сдвиги VS / HS / SB, ПЗУ палитры РТ4 таблицей), `ocean_vv51`, ВВ55 / ВИ53 (Целиков / Sorgelig, из Вектора), ВН59 KF8259 (MIT). XST: 1927 LUT (12 %), 16 RAMB16, 77 МГц, защёлок нет.
- **Sim** (`src/sim/run.sh`, Verilator, ~30 с): «TEST 1 PASSED», «TEST 8 PASSED» (таймер → IR4 → CALL 0020h; переход к тесту 8 патчем ПЗУ только в sim); кадры двух тестовых ПЗУ видео — без сдвигов и со сдвигами (VS = 05, HS = 0B: слово, прочитанное в гашении, заворот строк, сдвиг по точкам) — монохром, цвет, окно BLNK **точка в точку = кадры схемной модели** (`src/sim/ref`). Тест со сдвигами нашёл ошибку SC5 (DD22.1: C5 \| GC). Отдельно (долго, не в наборе): «TEST 3 PASSED» (ОЗУ 128 КБ, 5 с машины / 4 мин счёта); тест 4 за 8,5 с не закончился (не ошибка — не досчитан); тесты 2, 5–7 не гонялись (2 — сдвиги с паузами в секунды, 5 / 6 — лента, 7 — клавиатура на терминал). Монитор 240/7 + CP/M → «OKEAH-240 CP/M (V2.2) REL.5», `A>`, `DIR` с клавиатуры 240/7 → `NO FILE` (`CPM=1 run.sh`); HARDWARE MONITOR+ + CP/M с дисководом без контроллера → «48K CP/M (V2.2) REL.7/2D, 64K RAM DISK (A:), 180K FD (B:)», `A>`.
- **Цвета**: таблица 2 МПСС точно совпадает с тем же ПЗУ РТ4 при разводке D1 = R, D2 = G, D3 = B (все строки: монохром, палитры 0–3, 6); в реплике R ← D3, G ← D1, B ← D2 (циклический сдвиг трёх проводов). В ядре — пункт OSD «Цвета: МПСС / реплика»; что по умолчанию — решает пользователь.
- **Клавиатуры** (обе — с контроллером, строб → IR1, опрос IRR): 240/7 — ASCII 7 бит на PA, подтверждение импульсом PC7; HARDWARE MONITOR+ — PA = одна единица (столбец), PC0–3 = строка 0–10, PB5 / PB6 — модификаторы, подтверждение PC4.
- **Пресеты «Модель»** (решение 2, предложение — решает пользователь): «240.2» — Монитор 240/7 + CP/M REL.5, клавиатура ASCII; «Turbo» — HARDWARE MONITOR+ + CP/M REL.7/2D, позиционная клавиатура (дисковод B: — после Ф4); «Тест» — тест-программа МПСС (вывод на USB-UART). «240» без сдвигателей: дампа ПЗУ первого 240 нет, Монитор 240/7 уже пишет C0 / C2 — такой пресет с ним сломает прокрутку; можно оставить пунктом «сдвигатели выкл.» для своих ПЗУ.
- **HDMI**: кадр Океана с удвоением строк = 768 × 640 при 24,576 МГц, 50 Гц (как Вектор с его 624 строками; 640 — больше 625 у 576p). Пробуем в Ф1 на мониторе пользователя и на захвате; не примут — буфер кадра.

### Ф1. Океан на Mini G + базовый набор платы
- Верх Mini G (из vector06c): PLL, удвоитель строк, HDMI + звук, PS/2 / USB клавиатура → ASCII-контроллер (позиционный код + строб, IRQ1) и матрица 8 × 11 (по пресету), F12 = сброс.
- OSD: Модель, Reset, палитра «как РТ4 / подобранная» (если в Ф0 подтвердится расхождение цветов), Tape monitor. Вид OSD — кадр и «да» пользователя до слияния.
- **Базовый набор платы (правило 2026-11-22):** `audio_peaks` из итогового микса (CMD 0x70 / 0x71); TAPE_IN (через регистр) → 41h B2 (+ B3 «есть сигнал»), TAPE_OUT ← ЦАП E2 C0–C2, `kg_tape_monitor` в миксе, пункт «Tape monitor» Off / In / Out / Both (Menu+T); MIDI_TX = 1 (у Океана MIDI нет); АЦП PCM1808 (линейный вход в микс); FT_CLK_OUT ≈ 8 МГц.
- ВВ51 → USB-UART MCU (порт 0): тест-программа и Монитор с терминалом на ПК.
- `.kg` со всеми ПЗУ (решение 6), сборки через `src/Makefile`, map / PAR `-t 2` сначала. Проверка на плате и на захвате (после «да» на захват).

**Ход Ф1 (2026-11-25, ветка `f1-minig`):** верх Mini G (`rtl/karabas_minig_top.v`): DCM 24/25 + PLL /2 ×41 (VCO 984): машина 49,2 МГц (+0,1 % к 49,152), HDMI 24,6 МГц, `ocean_scan2x` 768 × 640 (50,05 Гц, активно 640 × 576, экран 512 × 512 по центру); все ПЗУ в `.kg` (080000…088000), пункты OSD: Модель (240.2 / Turbo / Тест), Цвета (реплика / МПСС, по умолчанию реплика — пользователь 2026-11-25), Tape monitor (Menu+T), Reset (F12); `ocean_kbd` (PS/2 → ASCII 240/7 и позиционная MONITOR+), ВВ51 ↔ порт 0 MCU байтами; базовый набор платы. Сборка 26112501: 28 % LUT, 18 RAMB16, тайминги сошлись. Sim: обе CP/M до `A>`, `DIR` через `ocean_kbd` на обеих клавиатурах, HDMI-кадр удвоителя. На плате (Mini G, 2026-11-25): 26112501 — CP/M REL.5 и REL.7 загружаются, `DIR` с обеих клавиатур, OSD, Bell в звуке HDMI, захват принял 768 × 640; 26112502 (порт 0 MCU включён) — «TEST 1 PASSED» / «TEST 2 PASSED» на USB-UART (if02), байт с if02 доходит до ВВ51 (тест 2 нарисовал шахматы). 26112503: `ENABLE_AUX` для уровней звука (MATRIX_CMD без него не уходил).

### Ф2. Память, лента, звук
- «Электронный диск»: доп. ОЗУ 64 КБ, опция 512 КБ (пункт OSD, если ПЗУ его знают); `FL` образа электронного диска (загрузка / выгрузка — по образцу квазидиска Вектора).
- Лента: `.wav` файлом (как `v06c_tape`) + вход платы; форматы Монитора — 500 и 6000 бод.
- Звук: Bell, ВИ53 канал 0 / 2 если они выведены на звук (по схеме), фильтр ЦАП ленты.

**Ход Ф2 (2026-11-25, ветка `f2`):**
- **Электронный диск на карте** (`ocean_rdisk` + `kg_bk_ram` из modules): обе CP/M держат диск A: в странице 1 (64 КБ, одинаковый DPB: SPT 16, блок 1 КБ, DSM 63, DRM 31); файл `<каталог ядра>/saves/ramdisk.sav` (core.json `loader.save_name`, `make_core.py` пишет запись LOADER 14 байт), читается до старта ЦП, записанные секторы сохраняются через секунду после последней записи; прошивка сбрасывает их и перед сменой ядра. CP/M при холодном старте форматирует диск, если в 0006 не её BDOS (BC06 у REL.5, BA06 у REL.7 — проверка реальной машины, сохраняющая диск при кнопке сброса): при непустом файле ядро пишет это слово до старта ЦП и при смене модели. Модель «Тест» (затирает всё ОЗУ) — без файла. Sim: оба CP/M видят файл подставленного образа; `tb_rdisk` (модель монтировщика): чтение, слово BDOS, автосохранение, смена модели, «Тест» не сохраняет.
- **Лента**: `.wav` пунктом FL (слот 6) → SRAM 200000 → `ocean_tape` (из Вектора) → PB2, вход платы, когда не играет; Tape play / stop. Выход: ЦАП E2 C0–C2 (веса 4 / 2 / 1) через дифференцирующую цепь — бит 1 при росте уровня, 0 при падении (Монитор пишет 03 / 04, тест — переключает C1). Sim (`TAPE=1`): сигнал теста 5 → `.wav` → тест 6 читает его: сплошные «+».
- **ВВ51**: приёмник ждал стоп-бит не всегда — после байта ловил ложный старт (бит 7 = 0); исправлено.
- `ocean_aux`: порт aux SRAM на четырёх хозяев (загрузчик, слово BDOS, `kg_bk_ram`, лента) с удержанием доступа до подтверждения.
